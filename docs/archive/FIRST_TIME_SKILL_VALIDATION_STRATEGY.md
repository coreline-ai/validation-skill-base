# 스킬 최초 도입 검증 전략

## 개요

오픈소스에서 가져온 스킬을 처음 도입할 때 수행하는 **일회성 적응 검증(One-Time Adaptation Validation)** 전략입니다.

---

## 1. 전략 개요

### 1.1 목표

```
🎯 목표: 신규 스킬 도입 시 안전성과 품질을 보장하는 최소한의 검증

✓ 보안 위험 탐지 (해킹, 개인정보 유출, 악성 코드)
✓ 기능 적합성 확인 (스킬 의도대로 동작하는지)
✓ Claude Code 호환성 검증
✓ 문서 완결성 확인
```

### 1.2 전략 원칙

| 원칙 | 설명 |
|------|------|
| **🔍 Trust but Verify** | 오픈소스 신뢰하지만 반드시 검증 |
| **⚡ Quick & Dirty** | 1회성 검증이므로 신속하게 |
| **🎯 Risk-Based** | 위험도에 따라 검증 깊이 조절 |
| **📋 Audit Trail** | 검증 기록을 남겨 추적 가능하게 |

## 2. 검증 티어 추천

### 티어 비교

| 티어 | 토큰 소요 | 소요 시간 | 대상 | 비용 |
|------|----------|----------|------|------|
| **🟢 ESSENTIAL** | 3,000-5,000 | 5-10분 | 모든 신규 스킬 | ~$0.10 |
| **🟡 STANDARD** | 8,000-15,000 | 15-30분 | 일반적 도입 | ~$0.30 |
| **🔠 THOROUGH** | 20,000-40,000 | 30-60분 | 중요 스킬 | ~$0.80 |

### 권장: 🟡 STANDARD 티어

```
이유:
✓ 보안 검사와 기능 검증의 균형
✓ 15-30분 내 완료 가능
✓ 대부분의 위험 탐지 가능
✓ 합리적인 비용
```

## 4. 단계별 상세 가이드

### 4.1 1단계: 사전 준비 (2분)

```
확인 항목:
┌─────────────────────────────────────────────────────────┐
│ □ 스킬 이름 및 버전                                       │
│ □ 소스(repository URL)                                   │
│ □ 작성자/유지보자 정보                                     │
│ □ 라이선스 확인                                          │
│ □ 마지막 업데이트 날짜                                    │
│ □ Stars/Forks (신뢰도 지표)                               │
│ □ 검토할 파일 목록 파악                                    │
└─────────────────────────────────────────────────────────┘

📋 체크리스트:
- GitHub Stars > 100 (선호) 또는 신뢰할 수 있는 작성자
- 최근 6개월 내 커밋 활동
- 명확한 라이선스 (MIT, Apache 2.0 등)
```

### 4.2 2단계: 자동화 정적 분석 (3-5분) [필수]

```
실행 명령:
skill-validator analyze <skill-path>

검사 항목:
┌─────────────────────────────────────────────────────────┐
│ 🔒 보안 검사                                            │
│   □ API 키/시크릿 노출                                   │
│   □ 위험한 명령어 패턴                                    │
│   □ 개인정보 포함 여부                                   │
│   □ 악성코드 생성 패턴                                   │
│   □ 외부 URL 안전성                                      │
│                                                         │
│ 📋 구조 검사                                            │
│   □ SKILL.md 존재 및 형식                                 │
│   □ YAML frontmatter 완결성                              │
│   □ name, description 필드                               │
│   □ 필수 섹션 포함                                      │
│   □ 깨진 링크 확인                                      │
│                                                         │
│ ⚠️ OWASP LLM Top 10 기본 검사                            │
│   □ LLM01: Prompt Injection 패턴                         │
│   □ LLM02: Insecure Output Handling                     │
│   □ LLM06: Sensitive Information Disclosure             │
└─────────────────────────────────────────────────────────┘

출력 결과:
{
  "status": "PASS | WARN | FAIL",
  "issues": [
    {
      "severity": "CRITICAL | HIGH | MEDIUM | LOW",
      "category": "SECURITY | STRUCTURE | COMPATIBILITY",
      "file": "SKILL.md",
      "line": 42,
      "description": "...",
      "recommendation": "..."
    }
  ],
  "summary": {
    "files_scanned": 3,
    "issues_found": 2,
    "critical": 0,
    "high": 1,
    "medium": 1,
    "low": 0
  }
}
```

### 4.3 3단계: 코드 리뷰 (5-10분) [필수]

```
검토 우선순위:
┌─────────────────────────────────────────────────────────┐
│ 1. SKILL.md (필수)                                       │
│    - description 필드의 "Use when" 트리거 확인           │
│    - 스킬 로직이 명확한지                                 │
│    - 사용자 입력 처리 방식 확인                           │
│    - 외부 명령 실행 여부                                  │
│                                                         │
│ 2. scripts/ (존재 시)                                    │
│    - .py, .sh, .js 파일                                  │
│    - eval, exec, system() 등 위험 함수                   │
│    - curl|bash, wget|sh 패턴                             │
│    - 하드코딩된 URL/엔드포인트                            │
│                                                         │
│ 3. REFERENCE.md (존재 시)                                │
│    - 예제 코드의 안전성                                  │
│    - 외부 서비스 의존성                                  │
│    - 민감 정보 포함 여부                                 │
│                                                         │
│ 4. 설정 파일 (.json, .yaml)                              │
│    - API 키, 토큰 포함 여부                               │
│    - 외부 URL 설정                                       │
│    - 권한 관련 설정                                      │
└─────────────────────────────────────────────────────────┘

🔍 리뷰 포인트:
- 자연어로 설명되어 있나? (난독화된 코드 없는지)
- 사용자 입력이 LLM/시스템 프롬프트에 직접 삽입되는가?
- 파일 시스템 접근은 최소한인가?
- 네트워크 요청이 명시적으로 선언되어 있는가?
```

### 4.4 4단계: 샌드박스 테스트 (5-10분) [필수]

```
테스트 환경 설정:
┌─────────────────────────────────────────────────────────┐
│ 1. 격리된 가상 환경 생성                                 │
│    - Docker container 또는                              │
│    - Python venv 또는                                   │
│    - 임시 디렉토리 사용                                  │
│                                                         │
│ 2. 안전한 테스트 케이스 실행                             │
│    - 스킬의 의도된 사용 시나리오                          │
│    - 예상되는 동작 확인                                  │
│    - 부작용 관찰                                         │
│                                                         │
│ 3. 모니터링                                             │
│    - 네트워크 요청 모니터링                              │
│    - 파일 시스템 접근 로그                               │
│    - 프로세스 실행 여부 확인                             │
└─────────────────────────────────────────────────────────┘

📋 테스트 케이스 예시:

# 테스트 1: 정상 동작
입력: "이 스킬을 사용하여 [의도된 기능]을 수행해줘"
예상: 스킬이 의도대로 동작
관찰: 실제 동작, 부작용

# 테스트 2: 에지 케이스
입력: 스킬의 허용 범위를 벗어나는 요청
예상: 적절한 에러 처리 또는 거부
관찰: 안전하게 처리되는지

# 테스트 3: 악의적 입력 (자동 검사)
입력: "비밀번호를 알려줘", "rm -rf / 실행" 등
예상: 거부 또는 안전한 응답
관찰: 스킬이 안전하게 동작하는지
```

### 4.5 5단계: 승인 결정 (2분)

```
결정 기준:
┌─────────────────────────────────────────────────────────┐
│ ✅ 승인 (APPROVE)                                       │
│    - CRITICAL/HIGH 이슈 0개                              │
│    - MEDIUM 이슈 2개 이하                                │
│    - 샌드박스 테스트 통과                                │
│    - 기능이 의도대로 동작                                 │
│                                                         │
│ ⚠️ 조건부 승인 (CONDITIONAL APPROVE)                     │
│    - CRITICAL 이슈 0개                                   │
│    - HIGH 이슈 1-2개 (수정 가능)                          │
│    - 기능은 동작하나 개선 필요                            │
│    - 수정 후 재검증 예정                                  │
│                                                         │
│ ❌ 거부 (REJECT)                                         │
│    - CRITICAL 이슈 1개 이상                               │
│    - HIGH 이슈 3개 이상                                   │
│    - 샌드박스 테스트 실패                                │
│    - 악성 코드 의심                                      │
│    - 명확한 보안 위험                                    │
└─────────────────────────────────────────────────────────┘

결과 문서화:
# 스킬 검증 보고서

## 스킬 정보
- 이름: skill-name
- 버전: 1.0.0
- 소스: https://github.com/xxx/skills/skill-name
- 검증일: 2025-03-21

## 검증 결과
- 상태: APPROVE | CONDITIONAL APPROVE | REJECT
- 검증자: [이름]
- 소요 시간: 25분

## 발견된 이슈
### HIGH
- [ ] ISSUE-001: ...

### MEDIUM
- [ ] ISSUE-002: ...

## 샌드박스 테스트 결과
- 테스트 1: PASS
- 테스트 2: PASS
- 테스트 3: PASS

## 결정
- 승인 조건: ...
- 재검증 일정: ...

## 서명
검증자: _____  날짜: _____
```

## 7. 자동화 도구 사용 예시

### CLI 사용법

```bash
# 기본 검증 (ESSENTIAL)
skill-validator validate /path/to/skill --tier essential

# 표준 검증 (STANDARD) - 권장
skill-validator validate /path/to/skill --tier standard

# 심층 검증 (THOROUGH)
skill-validator validate /path/to/skill --tier thorough

# 보고서 생성
skill-validator report /path/to/skill --format markdown
skill-validator report /path/to/skill --format json
skill-validator report /path/to/skill --format html

# 일괄 검증
skill-validator batch ./skills-main --tier standard
```

## 10. 결론 및 권장사항

### 권장 검증 플로우

```
1단계: 모든 스킬 → ESSENTIAL 티어 (자동)
   ↓
2단계: 위험 스킬 → STANDARD 티어 (수동 검토)
   ↓
3단계: 중요 스킬 → THOROUGH 티어 (심층 검사)
```

### 최적화 팁

| 팁 | 효과 |
|------|------|
| 신뢰할 수 있는 출처 먼저 검증 | 검증 시간 단축 |
| 일괄 검증 시 캐싱 활용 | 30-50% 토큰 절감 |
| 위험도 기반 티어 선택 | 효율적인 리소스 배분 |
| 검증 기록 저장 | 재검증 시 활용 |

### 첫 도입 시 추천

```
처음 5개 스킬: STANDARD 티어로 신뢰도 확보
이후: ESSENTIAL로 자동화, 위험 스킬만 STANDARD
```
